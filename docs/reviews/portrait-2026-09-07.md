# Independent portrait functional review · 2026-09-07

**Verdict: SHIP within the reviewed scope.** No concrete blocking defect remains in portrait source handling, actual bundled detector output, crop bounds, inline data validation or session preservation. This review does not certify appearance in Gmail or other email clients.

## Final verification

The final `apply()` cancels pending source work only when the patch includes `portraitData` or `portraitUrl`. `sync()` fingerprints those two source fields. Shape and Size edits therefore preserve pending local loading and face detection, while a newer applied source or restored session still invalidates stale hosted-photo responses.

The formerly failing regressions now pass in `tests/portrait-core.test.mjs`:

- `changing portrait shape during file loading keeps the selected upload`
- `changing portrait size during detection preserves the smart crop result`

The final independent rerun of `node --test tests/portrait-core.test.mjs tests/design-rendering.test.mjs` reported **22 pass / 0 fail**: 13 portrait tests and 9 renderer tests. The interaction harness executes the actual controls with explicitly deferred load/detection promises; it does not approximate browser layout. The verdict also relies on actual detector ground truth and source inspection below, not the pass count alone.

## Fixed defects independently rechecked

- Header-only PNG/JPEG values formerly passed core validation and session serialization. The hardened validator now rejects the three independently chosen truncated fixtures, while normal PNG session round trips still pass. Validation now checks image structure and PNG chunk CRCs; this is not a full JPEG entropy decoder.
- A slow hosted-photo response formerly could replace a newer manually applied crop. The newer crop now survives the late response.
- A slow hosted-photo response formerly could replace a restored session's portrait. Restored state now survives the late response.
- Applying a crop while the current draft is invalid now reports the validation error without claiming that a photo was added.

## Actual detector evidence

The fixture is NASA's public-domain 512 × 512 RGB portrait of astronaut Eileen Collins, taken from the official scikit-image v0.24.0 repository. [scikit-image documents its source and public-domain status](https://scikit-image.org/docs/0.24.x/api/skimage.data.html#skimage.data.astronaut). The exact downloaded file and attribution are in `tests/fixtures/`.

- Fixture SHA-256: `88431cd9653ccd539741b555fb0a46b61558b301d4110412b5bc28b5e3ea6cb5`.
- Node built-ins decode the fixture's actual PNG RGB pixels; the production grayscale weights are applied.
- The actual `portrait-worker.js`, `vendor/pico.js` and `vendor/facefinder.bin` execute in a VM. No fake detector result is substituted for this evidence.
- Detection: x **169.9072**, y **58.9072**, width/height **104.5856**, score **48.2752**. Its center and size match the known face, rather than merely asserting that some detection exists.
- Production smart crop: x **104.5412**, y **3.9998**, square size **235.3176**. It encloses the known face rectangle x=175–280, y=60–175 and stays within the 512 × 512 source.
- The lead's separate browser upload check reported zoom **2.18×**, horizontal position **37.8**, vertical position **1.4** and successful face detection. Those control values agree with this critic's independently computed geometry; the critic did not operate that browser check.
- A second test composites two differently sized copies in pixel memory. Both faces are detected and returned largest first.
- A uniform gray image produces zero detections. Oversized/malformed worker input and an incomplete model are rejected.
- The worker requests only the local `vendor/facefinder.bin` and sets `credentials: 'omit'`.

## Other checks

Crop geometry stays finite and within source bounds across 1-pixel through 1800-pixel dimensions, zoom values below/above limits, positions outside 0–100, NaN and infinity. Unsupported formats, empty files, >12 MiB input, malformed image-load errors and >60-megapixel decoded dimensions are rejected, with temporary object URLs revoked. The decode-error paths use controlled Image fixtures; real browser decoding is owned by the lead's interactive checks.

The latest selected upload wins when two file loads finish in reverse order. Non-square hosted photos are rejected without changing the saved portrait. A local portrait's data, shape, size, selected design and Photo tab round-trip through a session; old 23-field drafts migrate with no portrait and the original design.

The renderer suite verifies that local portrait data is included in preview/PNG markup, while copied email HTML requires a public HTTPS photo URL. All seven designs retain portrait dimensions, optional contacts and links, with bounded declared dimensions. The review does not infer rendered layout from those string checks.

Final source inspection confirms that rich-copy and HTML-download handlers catch the local-only portrait error and send the user to the Photo panel. The plain-text clipboard companion remains text only. The new Photo panel inset, native file-input overlay and focus treatment are confined to editor controls; they do not modify signature export markup. Visual usability of that inset remains part of the lead's browser review.

## Limits

This is one licensed positive subject, plus a two-size composite and a no-face negative. It is not a face-detection accuracy benchmark, demographic evaluation, profile-pose guarantee or live Gmail paste/send test. Hosted photo availability, cross-origin access for PNG export, and recipient email-client image handling remain external dependencies. The original uncommitted photo and crop controls are not session data; only the applied, stripped crop is preserved.
